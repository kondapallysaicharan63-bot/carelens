# 10 — Web-first plan (main track)

**Decision (2026-11-28):** CareLens ships first as a **static HTTPS website** that runs entirely
on the visitor's device (phone or laptop camera + microphone). The Jetson edge box is a
**later, optional track** using the same Python core. Real-world validation against an
Apple Watch comes later; until then the work is driven by synthetic and recorded-sample tests.

Not a medical device. Wellbeing trends and demonstration only — never diagnosis or emergency use.

## 1. Architecture

```
 browser (phone / laptop) — nothing leaves the device
 ┌───────────────────────────────────────────────────────────────────────────┐
 │ consent gate → device picker (camera, mic, torch)                         │
 │   video frames ─▶ MediaPipe Tasks (WASM/WebGPU): face / pose / hand ─┐    │
 │   audio  ─▶ AudioWorklet ─▶ MediaPipe Audio Classifier (YAMNet) ─────┤    │
 │                                                                      ▼    │
 │                Web Worker: CareLens core (TypeScript port)                │
 │                  rPPG · contact PPG · breathing · fall/inactivity ·       │
 │                  cough · quality gating   ← params.json (shared)          │
 │                                                                      ▼    │
 │        UI: results by tier + quality meter · optional local session save  │
 │                       · CSV/JSON export → python -m carelens.accuracy     │
 └───────────────────────────────────────────────────────────────────────────┘
 Python CareLens (reference implementation + Jetson/edge runtime, later)
```

- **No upload, enforced, not just promised.** A Content-Security-Policy `<meta>` tag sets
  `connect-src 'self'` and allows no third-party origins. Models and WASM are self-hosted,
  so the page *cannot* send video, audio or results anywhere, and works offline once loaded.
- Signal processing runs in a **Web Worker**; inference runs on the main thread with
  `requestVideoFrameCallback`, falling back to `requestAnimationFrame`.
- **Storage is off by default.** Opt-in session summaries live in IndexedDB on the device,
  with a "Delete all" button; export is a file download (CSV/JSON).

## 2. Keeping Python and JS in sync

Python stays the **reference**. The browser core is a hand-written TypeScript port. Shipping
Pyodide (~10 MB, slow on phones) was rejected. Three mechanisms stop drift:

1. **`shared/params.json`** holds every band, window, threshold and quality gate in one file.
   Python loads it (pydantic-validated) and TS imports it (typed). A test fails if either side
   has a key the other lacks.
2. **`shared/fixtures/`** holds deterministic synthetic inputs plus the *Python reference outputs*:
   - PPG traces at known BPM with noise, motion bursts and lighting steps;
   - breathing traces;
   - tremor signals;
   - landmark sequences (fall, slow lie-down, sit-to-stand);
   - YAMNet score sequences for cough, snore and none;
   - short audio clips.

   They are generated by `python -m carelens.fixtures` and committed. They are small and
   synthetic only, never footage. `pytest` and `vitest` both run them: JS must match Python
   within stated tolerances (e.g. ≤ 0.5 bpm), and must make **the same quality-gate decision**
   (number shown vs withheld).
3. **CI** (GitHub Actions) runs pytest, vitest, typecheck and a **fixture-freshness check**
   that regenerates the fixtures and fails on any diff.

ML models (MediaPipe) are not ported. Parity is defined from their landmark and score outputs
onward.

## 5. Hosting

- **Local:** `cd web && npm run dev` serves HTTPS on the LAN (self-signed) and prints the LAN URL,
  so a phone on the same Wi-Fi can open it. A browser needs HTTPS for camera/mic outside
  localhost. For a trusted certificate without the warning, use `mkcert` (documented).
- **Deploy:** `npm run build` produces a fully static `web/dist/`. A GitHub Pages workflow is
  included; Cloudflare Pages and Netlify work the same way.

## 6. Order of work

Each task is: Python reference → fixtures → TS port → parity + unit tests → code review → commit.

**Tier 1**

- **W0 scaffold**: site skeleton, disclaimer and separate camera/mic consent, device picker
  (flags **black frames** and suggests another camera, since on some laptops index 0 is black),
  torch toggle, light/dark themes, CSP, `params.json`, fixture generator, parity harness, CI,
  HTTPS dev, Pages deploy, README licence table.
- **W1 fingertip HR**: contact PPG, phone back camera + torch. First because it is the strongest
  signal and proves the DSP and parity chain end to end with no ML model.
- **W2 face HR**: rPPG with POS/CHROM on forehead/cheek ROIs from FaceLandmarker, motion and
  lighting rejection. This also upgrades the Python vitals, currently green-channel.
- **W3 pose**: presence, posture, fall and inactivity (port of `features`/`events`/`tracking`),
  plus breathing from chest/shoulder motion.
- **W4 audio**: breathing from breath sounds (close mic) and cough detection and count (YAMNet).
- **W5 session export + accuracy import**: `python -m carelens.accuracy --web-session …`, plus a
  Playwright end-to-end test that feeds the synthetic clip as a fake camera.

**Tier 2 (Experimental section)**

- **W6** HRV (RMSSD/SDNN, fingertip only)
- **W7** sit-to-stand (30 s count, 5× time), Timed Up and Go, walking speed
- **W8** hand tremor (3–12 Hz)
- **W9** blink rate, PERCLOS, activity level
- **W10** snoring + "possible pause" count, distress sounds as extra fall cues, speech/voice
  activity time. Built: `carelens/sleep_sounds.py` + `web/src/core/sleepSounds.ts` (pauses in
  breathing sounds, fall sound cue), per-label YAMNet detectors in `params.audio_events`, night mode
  (Wake Lock, dimmed, mic-only), session summaries in the export. Experimental; not a sleep test.
- **W11** optional "help" keyword (Vosk, off by default)

**Not offered, explained in the UI:** SpO₂, blood pressure, glucose, temperature, any disease
or diagnosis, emotion/mental-health scores, stroke/asymmetry screening, age or identity.

## 7. Jetson / edge track (later)

- **Same core:** the same Python core and the same `params.json`. Swap the pose provider for a
  TensorRT engine (RTMPose or trt_pose). Live RTSP capture, alerts, encrypted clips and SQLite
  are already built.
- **Website → box:** the website can optionally connect to a CareLens box on the LAN through a
  versioned read-only API (`/api/v1/…`, JSON schema in `shared/`) with a token.
  - HTTPS pages cannot call plain-HTTP LAN hosts (mixed content). So either the box serves the
    website itself, or the box gets a trusted certificate (mkcert / local CA).
- **Deferred to this track:** periodic checkpointing of long-running live runs to SQLite. The
  website keeps nothing server-side, so this is not needed now.

## 8. Wording rules carried over

- Every result shows its **tier** and a **quality meter**. Below the quality gate, no number is
  shown, only "signal too weak — hold still / add light".
- Audio cues use "possible … — check-in suggested", never "emergency detected" or "apnea".
